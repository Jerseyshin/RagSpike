# LightRAG 语料边界与入库约定

> 状态：Approved v0.1
>
> 确认日期：2026-10-18
>
> 确认人：项目负责人（用户）

## 1. 两阶段语料范围

### P0 管线试跑

先使用已经规范化和验收的 11 份 P0 文档、571 个固定分块，完成 LightRAG 入库、检索、引用和端到端问答链路验证。该阶段只验证管线能否正确运行及核心法规的初步效果，不代表用户原始清单的完整覆盖率。

### 正式首轮验证

正式首轮语料目标为 50 份具有正文候选的版本级文档：11 份 P0 加上完成规范化和人工验收后的 39 份 P1/P2。其余 11 份受限或失链文档延期处理，不进入本轮语料，也不进入相关指标分母。

## 2. P0 试跑输入

实际比较使用 `data/ingest/p0/records.jsonl`，其中每行是一个固定文本分块。普通向量 RAG 与 LightRAG 必须使用相同分块，避免切分差异污染选型结论。

每条记录包含：

- 稳定的 `record_id` 和 `document_id`；
- 法规正文 `content`；
- 法规名称、条款号、标题路径和小节标签；
- 施行日期和效力状态；
- 官方来源 URL、原始文件路径和 SHA-256。

`data/ingest/p0/documents.jsonl` 保存同一批规范化全文，仅用于来源重建或适配只接受全文的 API。若适配器重新切分全文，其结果不能直接与固定分块基线比较，必须单独标记为另一组实验变量。

## 3. 当前 11 份 P0 文档

1. 中华人民共和国个人信息保护法。
2. 中华人民共和国数据安全法。
3. 中华人民共和国网络安全法（2025年修正）。
4. 中华人民共和国民法典第一千零三十二条至第一千零三十九条。
5. 网络数据安全管理条例。
6. 数据出境安全评估办法。
7. 个人信息出境标准合同办法及标准合同附件。
8. 促进和规范数据跨境流动规定。
9. 个人信息保护合规审计管理办法。
10. App违法违规收集使用个人信息行为认定方法。
11. 常见类型移动互联网应用程序必要个人信息范围规定。

## 4. 明确排除

下列内容不得进入任何待评测的 RAG 知识库：

- `data/evaluation/` 中的问题、标准答案、必含要点、禁答项和证据集合；
- 盲测题或其答案；
- 下载日志、审计报告、阶段报告和执行日志；
- 未清洗的网页导航、页眉页脚和站点声明；
- 同一正文的重复 HTML、PDF 或附件副本；
- 只有元数据而没有已验收正文的文档；
- 11 份已延期的受限或失链文档。

原始文件只用于证据追溯，不直接作为检索语料。评测数据与知识库数据必须使用不同目录，并由入库脚本使用明确允许清单读取，禁止扫描整个 `data/` 目录。

## 5. 版本与实验隔离

- P0 试跑语料版本固定为 `cn-privacy-p0-v0.1`。
- 入库包清单记录文档数、分块数和内容哈希。
- 普通向量 RAG 与 LightRAG 分别使用独立存储目录，不复用索引。
- 39 份扩展正文完成验收后创建新的语料版本，不原地覆盖 P0 基线。
- 任何正文、元数据或切分变化都会产生新语料哈希，并触发完整回归。
